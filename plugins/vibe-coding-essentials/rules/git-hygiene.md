# Git and commit hygiene rules

Reusable across any software project. Applies when committing or managing source history.
Load via `/vibe-git-rules`.

## 1. Small atomic commits
One logical change per commit. Mixing a refactor, a feature, and a formatting sweep in one commit makes review, revert, and bisect impossible. Each commit should build and pass on its own.

## 2. Write meaningful commit messages
Imperative subject ("Add retry to upload", not "added retry"), under ~50 chars. Body explains why, not what — the diff already shows what. Link the issue/ticket. Future-you reads these to understand intent.

## 3. Never commit secrets
`.gitignore` env files, key files, credential dumps before first commit. Secret pushed once lives in history forever — rotate it, do not just delete the file. Run a secret scan before commit (see `vibe-secret-scan`).

## 4. Work on short-lived branches, not directly on main
Branch per feature/fix, merge via review. Short-lived branches reduce conflict pain and keep main releasable. Long-running branches drift and rot.

## 5. Never force-push shared branches
`--force` on a branch others use rewrites their history and destroys work. Force-push only your own un-pushed/un-shared branch, and prefer `--force-with-lease`.

## 6. Commit early, commit often
Checkpoint working states frequently — especially before and after large AI-generated changes. Small frequent commits make any bad change cheap to roll back. Don't hoard a day of work in one commit.

## 7. Review the diff before committing
Read what you stage. Never blind `git add -A && commit` on AI output — it sweeps in debug code, stray files, secrets, and unrelated edits. Stage intentionally (`git add -p`).

## 8. Lockfiles in, build artifacts out
Commit dependency lockfiles (reproducible installs). Keep build output, caches, `node_modules`, logs, local config, and large binaries out via `.gitignore`. Repo holds source, not generated bytes.

## 9. Clean your own history, merge shared work
Rebase/squash to tidy your own un-pushed branch before opening a PR. Once shared, merge instead of rewriting. Tidy history is a courtesy, not a license to rewrite what others depend on.

## 10. Sync before push
Pull/rebase onto the latest base before pushing to avoid divergent history and surprise conflicts. Resolve conflicts deliberately — never blindly accept "theirs" or "ours".
